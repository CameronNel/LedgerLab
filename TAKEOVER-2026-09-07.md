# LedgerLab: finance takeover continuation

## Status and purpose

This is a source-only extension of the supplied 7 September reliability continuation.
It has not changed a hosted site, remote repository, database, access setting or saved
user workspace. Read `TAKEOVER-VERIFICATION-2026-09-07.md` for the checks actually run.
The complete React/Vinext application still needs its locked dependency installation,
full typecheck, browser testing and build before deployment.

The user is a CA(SA) pivoting from audit into a financial-accountant or financial-manager
role. The new mode shifts the work from checking a preposted December case to owning
transaction processing, an inherited ledger, monthly closes and management outputs.
It is not professional certification or a replacement for supervised industry work.

## Starting a takeover

Open **Your finance desk**, choose a first month in calendar 2025, role and handover
condition, then confirm `START TAKEOVER`. The UI downloads the current saved-state
backup before requesting replacement and downloads an unsaved notebook separately.
A browser download is not proof the user retained that backup. The server requires the
explicit confirmation; the existing case is not silently converted.

The default is July, financial manager, messy handover, using the current seed.
Earlier source transactions and bank matches are inherited. The active month has no
learner postings. Later actuals are released only after closing and advancing. The
report-period selector is not the simulation clock and cannot unlock future posting.

January starts from the signed opening trial balance, so there are no planted inherited
current-year mistakes in that start month. February–December messy starts add three
current-year predecessor errors: an unsupported extra insurance release, a duplicate
professional-fee accrual and a correctly banked receipt moved into suspense. Their
supporting follow-ups are available; corrections retain the original history.

The financial-accountant track has core processing, controls and reporting work. The
financial-manager track additionally requires liquidity and investment deliverables
and a submitted 13-week cash forecast. The forecast is also available optionally to
financial accountants. Standard role deliverables recur monthly; the first month adds
the handover and December adds the AFS/board-support deliverable.

## Practical working sequence

1. Read the handover and managing director's monthly brief. Establish inherited cash,
   reporting dates, risks and priorities; do not accept predecessor sign-offs blindly.
2. Process source invoices with appropriate coding. Record receipts and payments as
   separate transactions. Retain contacts, source references and transaction dates.
3. Match the bank statement and investigate differences. Reconcile customer/supplier
   controls to independent statements, then set collection and payment priorities.
4. Recalculate payroll and investigate the HR exception. Reconcile the payroll controls
   to the register and bank, keeping preparation distinct from payment approval.
5. Prepare monthly adjustments and supporting account reconciliations. Inspect stock,
   assets, leases, cut-off, prepayments and tax controls using released evidence.
6. Prepare management reporting and role deliverables. Save drafts frequently. In the
   manager track, submit a cash forecast and explain funding/collection decisions.
7. Review the close gates, save the close conclusion, close the month and release the
   next month. Preserve the backup and export a portfolio at useful milestones.

## Checking and grading boundaries

On-the-job mode hides worked answers; guided support remains available and recorded.
Code/generated data contain the answer key, so this is not a proctored security boundary.

Numerical role fields are checked against the independent complete scenario, not the
learner's potentially incorrect books. The posting check compares source/date/account/
contact/cash-classification effects. Source-linked journals work without exercise IDs.
Evidence references and required written responses are validated. Written judgement is
**not** semantically graded or independently approved. Text length is a completion
threshold, not a measure of professional quality. Forecast arithmetic, structure and
completion are checked, but its commercial realism is not certified.

The close is case-specific. Additional sandbox invoices/journals remain supported, but
unrelated extra transactions or alternative timing/coding outside the canonical scenario
will block that scenario's close until reconciled or reversed. This is not an open-ended
production ledger accepting every defensible accounting treatment. Preserve correction
history; use the source dates within the open month when correcting the exercise.

A new financial posting reopens current-month submitted role work and forecasts.
Changing a forecast reopens its liquidity recommendation. Earlier closed periods remain
protected. Only the latest active close can be reopened; previous closed periods cannot
be casually backdated. Restoring a backup rechecks completed periods rather than trusting
an imported 'closed' flag.

Role/forecast drafts persist once saved. Their unsaved form edits currently warn on page
unload but may be lost when switching tasks, tabs or views. This differs from the global
notebook, whose unsaved draft survives workspace navigation. Save before moving away.

## Reporting and source integrity

Source documents and dated monthly asset-register snapshots are immutable across later
releases; tests compare their complete serialized contents. Future bank/payroll records,
asset additions and count/NRV actuals are withheld from the released company. Budgets and
contractual future lease/loan cash flows are planning information, not posted actuals.

Historical statement and inventory views use their selected month. Direct report exports
and the offline generator use the active takeover cutoff instead of silently using
December. Annual disclosure-note calculations are withheld from interim reports. The
original static December PDF links are not presented as takeover evidence.

December AFS work deliberately retains unresolved prior-year performance, related-party,
subsequent-event, going-concern and authorisation evidence gaps. A completed training
close does not turn that pack into complete statutory accounts or board approval.

## Preserved scope and omissions

This remains the existing fictional **AUD / calendar 2025 / single-entity** scenario.
The existing disclosed teaching tax and payroll rules were not changed or revalidated
as current law. CA(SA) is the user's qualification, not a request to silently relabel
Australian GST/PAYG/super as South African VAT/PAYE/UIF/SDL. There is no live banking,
payment execution, payroll filing, tax filing or production approval workflow.

Multi-entity consolidation, operational multicurrency, changing-cost inventory layers,
2026 operating months, full comparative statutory AFS, richer industry scenarios and
human-quality review of recommendations are not implemented by this continuation.
The same overtime exception and investment proposal recur as practice prompts; this is
not yet a fully branching simulation of different stakeholder responses each month.

## Implementation map

- `lib/accounting/career-types.ts`: optional saved takeover configuration, role outputs,
  monthly close records and forecasts.
- `lib/accounting/career.ts`: independent released scenario, inherited exceptions,
  immutable dated sources, source-linked work units and active-period boundaries.
- `lib/accounting/career-work.ts`: source-based quantitative rubrics, reports, forecast,
  case-close checks and saved-record validation.
- `lib/accounting/career-exports.ts`: work portfolio and forecast CSV.
- `components/ledgerlab/career.tsx`: setup, desk, source queue, deliverables, forecast,
  close/reopen/advance and links to the existing accounting workbenches.
- `engine.ts`: takeover commands, source invoice capture, period protections and
  invalidation. `companyForState` chooses the legacy or takeover scenario.
- Existing report/schedule/statement/invoice screens and offline exports now respect
  takeover periods. Legacy behaviour remains covered by the original suites.
- `career-check.ts`, extended `persistence-check.ts` and `render-check.tsx`, and the
  optional local browser driver contain targeted regression coverage.

Saved-state schema stays at version 1 with an optional `career` property. No database
migration or package dependency change is required. The role sub-schema has version 1.
Older backups without `career` keep the legacy December case. Frozen scenario caches
contain only seed/config-derived case data, not user journals or submissions.
